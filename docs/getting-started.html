Running GymRecover on your own computer

This walks you through everything, starting from the GitHub page, through downloading the code, installing the tools it needs, and starting up all three parts of the app. Follow the steps in order — nothing here assumes you've done this before.

⏱️ About 45–60 minutes 💻 Windows or Mac 🔗 github.com/phattrinh1995-beep/gymrecover

      First, a few words you'll keep seeing

      Skip this if you already know what a terminal or a repository is.

      WordWhat it means here
      Repository ("repo")A project's folder of code, stored on GitHub. GymRecover's repo is at the link above.
      CloneDownloading a copy of a repository onto your own computer.
      TerminalA window where you type text commands instead of clicking buttons. On Windows it's called PowerShell; on a Mac it's called Terminal.
      CommandA line of text you type into the terminal and press Enter to run.
      Package / dependencyA piece of code someone else wrote that this project uses. npm install downloads all of them for you.
      .env fileA small text file holding settings for your own computer, like which port to use. Each app has a template called .env.example you copy from.

      What you're about to set up

      GymRecover is three separate programs that all talk to each other. You'll start all three, each in its own terminal window.

      backend/

      The server

      Stores all the data and does all the logic. The other two apps can't work without this one running.

      mobile/

      The phone app

      What a patient or gym member would use. Runs in your web browser for this guide, no phone needed.

      web/

      The provider portal

      What a clinician or admin would use. Also runs in your browser.

      1

      Install the tools this project needs

      Two programs, both free. Install them before anything else.

      Node.js — runs the code

      1. Go to nodejs.org.
      2. Click the button offering the LTS version (LTS = "Long Term Support" — the stable one).
      3. Open the file you downloaded and click through the installer with the default options.
      💡
      Check it worked: open a terminal (see below) and type node --version. If you see something like v20.11.0, you're set.

      Git — downloads the code from GitHub

      1. Go to git-scm.com/downloads.
      2. Download the installer for your operating system and run it, default options are fine.
      💡
      Check it worked: in a terminal, type git --version. Any version number means it's installed.

      How to open a terminal

      WindowsClick the Start menu, type PowerShell, press Enter.
      MacPress Cmd+Space, type Terminal, press Enter.

      Every gray box with a Copy button below is a command — click Copy, click into your terminal window, paste it (Ctrl+V or Cmd+V), and press Enter.

      2

      Get access to the GitHub repository

      This repository is private, so you need to be signed in as an invited collaborator.

      1. If you don't have a GitHub account yet, create one free at github.com/signup.
      2. Ask whoever owns the project to add your GitHub username as a collaborator on the repository (GitHub → repo → Settings → Collaborators).
      3. Once added, you'll get an email invite — accept it.
      4. Visit the repository page and confirm you can see the file list (not a "404" or "access denied" page).
      3

      Download the code to your computer

      This is called "cloning" — it copies the whole repository into a folder.

      Open a terminal and go to wherever you'd like the project folder to live — for example your Desktop:

      terminal
      # Windows (PowerShell)
cd Desktop
# Mac
cd ~/Desktop

      Then clone the repository (this uses HTTPS, so the first time you clone or push, Git may open a browser window asking you to sign in to GitHub — go ahead and sign in there):

      terminal
      git clone https://github.com/phattrinh1995-beep/gymrecover.git
cd gymrecover
      ✅
      You now have a folder called gymrecover with three subfolders inside: backend, mobile, and web.
      4

      Set up and start the backend

      Do this first — the other two apps need it running.

      4a. Install its packages

      terminal
      cd backend
npm install

      This downloads everything the backend needs. It can take a couple of minutes and prints a lot of text — that's normal.

      4b. Create your settings file

      terminal
      # Windows (PowerShell)
copy .env.example .env
# Mac
cp .env.example .env

      Open the new .env file in any text editor (Notepad works fine) and leave everything as-is for local testing — the defaults are made to work out of the box, including AUTH_DEV_BYPASS=true, which lets you sign in without setting up a real login system.

      ⚠️
      Never set AUTH_DEV_BYPASS to true anywhere other than your own computer — it's explicitly blocked from running that way in production.

      4c. Start a local database

      This project uses a database called PostgreSQL, and includes a way to run a temporary one locally with a single command — no separate install needed:

      terminal
      npx prisma dev

      Leave this running — it'll print some connection info and then sit quietly. Open a new terminal window for every step from here on, and use cd to get back into the gymrecover/backend folder each time.

      4d. Set up the tables and load sample content

      In your new terminal window, back inside the backend folder:

      terminal
      npx prisma migrate deploy
npm run seed

      The first command creates all the database tables. The second loads sample (placeholder) exercises and recovery programs so the app isn't empty.

      4e. Start the backend

      terminal
      npm run start:dev
      ✅
      You'll see log lines ending with something like Nest application successfully started. Leave this terminal window open and running the whole time you're using the app.
      5

      Set up and start the mobile app

      Open a brand-new terminal window for this — keep the backend one running.

      terminal
      # from the gymrecover folder
cd mobile
npm install
# Windows
copy .env.example .env
# Mac
cp .env.example .env
npm run web

      After a short wait, this opens the app in your default web browser automatically. If it doesn't, it'll print a web address (something like http://localhost:8081) — open that yourself.

      6

      Set up and start the provider portal

      Another new terminal window, same idea.

      terminal
      # from the gymrecover folder
cd web
npm install
# Windows
copy .env.example .env
# Mac
cp .env.example .env
npm run dev

      This prints a local web address, usually http://localhost:5173 — open it in your browser.

      7

      Try it out

      As a member (mobile app, in your browser)

      On the mobile app's page, tap Get Started and enter any name and email — this local setup has no real login system, so it creates an account for you instantly. Walk through the questions to see the onboarding flow.

      As an admin (provider portal, in your browser)

      Sign in the same way on the web portal. To see the content-management screens, give your account admin rights from a terminal (in the backend folder):

      terminal
      npx tsx prisma/dev-grant-super-admin.ts you@example.com

      Use the exact email you signed in with, then refresh the portal page.

      If something goes wrong

      "node" / "npm" / "git" is not recognized

      The tool didn't finish installing, or you opened your terminal before installing it. Close the terminal window completely, reopen a new one, and try again — Windows and Mac only pick up newly installed programs in fresh terminal windows.

      "Port already in use" when starting something

      Something else on your computer is already using that address, often a leftover copy of the same app from before. Find and close any terminal windows still running an earlier npm run … command, or restart your computer.

      The mobile app or portal shows a blank page or can't reach the server

      Make sure all four windows from the Quick Reference table above are still running — closing the terminal (or the window) stops that piece of the app. Check the .env file in mobile or web points at the same address your backend printed on startup.

      Git asks for a username and password

      GitHub no longer accepts plain passwords here. Let Git open the browser sign-in window instead (it usually does this automatically on first clone) — sign in there once and it's remembered.

      I closed the "database" terminal window by accident

      Open a new terminal, go back into the backend folder, and run npx prisma dev again — your data is saved and will still be there.
